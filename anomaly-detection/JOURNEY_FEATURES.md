# مواصفات المؤشرات المقترحة لكل مسار

هذه وثيقة تصميم لمرحلة النموذج الأولي. كل البيانات والأمثلة الحالية اصطناعية. المؤشرات أدناه **مقترحات تحتاج موافقة مالك المسار والبيانات**؛ لا تمثل سياسة معتمدة ولا تُستخدم لاتخاذ قرار صرف أو رفض.

**تحديث 17 أكتوبر 2026:** أضيفت مؤشرات خاصة بكل مسار من مسارات التقييم، وتدخل كل مجموعة إلى نموذج اصطناعي مستقل وتحفظ مع سجل التقييم. لا تدخل الشاشة أرقام حسابات أو IBAN خامة أو أسماء أو أرقام هوية أو بيانات اتصال خامة. لم تعتمد تعريفات المؤشرات ولم تجر معايرة على بيانات تشغيلية.

### الحقول الاصطناعية المطبقة في شاشة التقييم

- **Retirement:** أشهر الاشتراك المثبتة، أشهر الفجوات، تغير الأجر قبل الطلب، التصحيحات الرجعية، عدد فترات العمل المتداخلة وأشهر التداخل.
- **Maternity Benefit:** أشهر الاشتراك في نافذة الأهلية، الأيام بين الحدث والطلب، تغير الأجر، مدة علاقة العمل، الطلبات المتزامنة، والتصحيحات الرجعية.
- **Contribution & Wage:** نسبة العاملين ذوي التغير الجوهري، وسيط تغير الأجر، تأخر الملف، إعادة الإرسال، التصحيحات الرجعية، ارتباط العمال بمنشآت متعددة، وفرق مطابقة الإجماليات.

هذه الحقول قيَم اختبار يدوي وليست مستخرجة تلقائيًا من أنظمة تشغيلية؛ يجب اعتماد تعريفاتها ومصادرها ونوافذها قبل الربط بأي بيانات حقيقية.

## قواعد تنفيذ مشتركة

1. تعريف كل ميزة بوحدة واضحة ونافذة زمنية ومصدر ووقت توفر؛ لا تستخدم أحداثًا لم تكن معروفة وقت التقييم.
2. لا تدخل الأسماء أو أرقام الهوية أو الآيبان أو أرقام الهاتف الخام في النموذج. تستخدم مراجع مستعارة لحساب الروابط والتكرار عند إجازة مالك البيانات.
3. المدينة والمنطقة والجنسية والخصائص المحمية لا ترفع المخاطر بذاتها. أي استخدام لها يحتاج مبررًا ومراجعة أثر وعدالة مستقلة.
4. نقص حقل مطلوب يؤدي إلى حالة «استكمال الأدلة» أو خفض الثقة؛ لا يعوض بقيمة صفر ولا ينتج عنه تصنيف منخفض تلقائيًا.
5. نتيجة المختص (مشروع/سليم/احتيال مؤكد) تبقى مخرجًا بشريًا منفصلًا، ولا تدخل ضمن ميزات الحالة نفسها. لا تُستخدم للتدريب قبل مراجعة جودة الوسم والموافقة.
6. لا تجمع درجات المسارات أو تقارن مئيناتها كما لو كانت مقياسًا واحدًا؛ لكل نموذج مرجع وإصدار وعتبة مستقلة.
7. قبل أي استخدام خارج العرض التجريبي: اعتماد المالك للحقول والتعريفات، ثم تقييم زمني منفصل، تحليل الإيجابيات الكاذبة والسلبيات الكاذبة حسب الفئات المسموح بها، ومراجعة الخصوصية والأمن.

## معيار اكتمال المسار

يعد مخطط المسار جاهزًا للتنفيذ بعد توثيق: مالك الحقل ومصدره، تعريف الميزة، الوحدة والنافذة، وقت الإتاحة، قواعد القيم المفقودة، أمثلة سليمة/غير معتادة معتمدة من المجال، ومالك قرار الإحالة. إلى أن تكتمل هذه العناصر يبقى نموذج المسار اصطناعيًا واستكشافيًا.

## دورة تدريب النماذج الاصطناعية

لا يتطلب المشروع رفع ملفات CSV. يولد كل مسار بيانات اصطناعية ثابتة البذرة، ويفصلها إلى مجموعات تدريب ومعايرة واختبار. يبني مدرب الرحلات خمسة نماذج Isolation Forest ويحفظ الأشجار والعتبات والنطاقات المرجعية ونتائج الاختبار في `anomaly-detection/data/journey-models.json`. يشغل الباكند هذه النماذج المحفوظة بدل إعادة توليدها عند كل تشغيل.

يعاد توليد نماذج المسارات الخمسة بالأمر `npm run train:journeys` من مجلد `anomaly-detection`. يستخدم كل مسار 1,024 حالة تدريب، و1,000 حالة معايرة، و800 حالة اختبار اصطناعية. تتوفر الأعداد وإصدار النموذج وملخص precision/recall ومعدل الإنذارات الكاذبة عبر نقطة الباكند `/journey-models`. نموذج SANED يظل مدربًا بسكربت Python المنفصل وملفاته الحالية.

هذه الاختبارات تقيس فقط أداء النماذج مقابل الحالات التي يولدها المشروع؛ لا تمثل نتائج واقعية، ولا تستخدم أحكام مختصين حقيقية. التقييم التشغيلي يتطلب مستقبلًا تعريفات ميزات معتمدة ومراجعة مستقلة، لكنه ليس مطلوبًا لتشغيل عرض الهاكثون الاصطناعي.
